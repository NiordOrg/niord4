## The order of work (re-based 2026-10-06)

The phases below keep their numbers — everything links to them — but they are no longer the sequence. The sequence is five steps, and two facts of 2026-10-06 shaped it: Niord is an open source product and `niord-dk`/`niord-gl` are SIFA's two installations of it, so the split is the product's natural shape, not an optional step; and **staging may be down for as long as the split takes** — nobody depends on it until then — while **from step C on it runs around the clock**. So nothing that exists to keep staging fresh is a prerequisite for the split, and everything that keeps it running is built in step C.

| Step | Phases | Delivers | Why in this place |
|---|---|---|---|
| **A** | 0, 1 (*Before the split*) | the last pre-split item: the cross-repository Packages read. The bundles in Packages and the seed off the DK module are done (#128, #129) | nothing else blocks the split |
| **B** | 1 | **the split**: `SIFA-DK/niord-dk` and `SIFA-DK/niord-gl` from `git filter-repo`, each with a pipeline **run by hand or by dispatch** that builds its image against the base version it names and pushes it to Harbor; the country modules leave `niord-ng`, which is the product repository in place | the product stops carrying SIFA's installations; no environment depends on the images yet, so the pipelines can be shaped calmly |
| **C** | 3, 4, 5 | **the environments**: DK and GL staging from the country images through Argo CD (the chart seams of `devops-niord` open issue 1 first), prod, the promote, the rollback drill. GL comes with DK: its files exist. **From here staging runs around the clock**, with the two routine signals (synced, failed) in place; its pins move by hand until step D | the core promise — a version in git, a button to prod |
| **D** | the audit, the move, 2 | **going public**: the content audit, `niord-ng` → `NiordOrg/niord4`, public, as a fresh repository with no history and the versions going on from 4.0.182 (decided 2026-11-03, decision 136, the name and the version 2026-11-17; the SIFA-DK repositories stay private for the history), the two country repositories public, secret scanning on — the checklist [Step D: at the move](#step-d-at-the-move); the bump chain (Phase 2) is built before step D on the private repositories: the Base bump workflow (2026-11-02), and the Niord base bump app being built (2026-11-03, F8), its registration and install the owner's; and the sharded IT suite | while `niord-ng` is private a move costs about 4 to 5 billed minutes per country (estimated), about 380 of the 2,000 a month for two countries; from the move, public repositories' minutes are free; a staging that is kept current by hand in the meantime is the accepted price |
| **E** | 6, 7, 8 | ephemeral environments, backups and snapshots, the smoke test (the public site's deployment in the base chart is done, 2026-11-10; the frontend chain was built as the country split, [`docs/fe-country-split-plan.md`](../../../docs/fe-country-split-plan.md)) | after the above; each can wait |

**What this takes out of the way of the split (2026-10-06):**

- **No hands-free chain before step D.** A country pipeline runs when someone asks for an image of a given base version (a `workflow_dispatch` with the version as input); the deploy repo's pins move by hand, as they do today, also for the around-the-clock staging of step C. This also answers the trigger question while the repositories are private: on demand, which costs nothing between asks.
- **Staging ran through the split after all.** DK and GL staging have run on the test cluster since 2026-09-26/29 (the plan said "parked" until 2026-10-06, wrongly); the first step C item moves them to the images the country repositories build. The staging smoke test stays Phase 7 (step E), and the rollback drill is done once, when prod values exist.
- **No ephemeral environments, PR images or sharded integration suite** before step D; none of them is free on a private repository.
- **The promote starts minimal**: copy the pins, open the merge request; the preconditions (staging healthy, DK equals GL, smoke green) arrive with the things they check.
- **Phase 2's "done when" (one human action per country, the bump PR's review and merge (the owner, 2026-11-01); 20–40 minutes without the waits)** is a step D goal, not a gate for step C.

The rest of this section's conventions stand: each phase ends with something **demonstrable**; effort figures are indicative working days for one person who knows the codebase, relative sizing rather than commitments; the cutover of the *live* DK production system onto this platform is a separate, coordinated event outside this plan (step C delivers the platform it will cut over to; the SECOM side is `devops-niord/docs/cutover-readiness.md`).

## Risks and fallbacks

| Risk | Impact | Fallback |
|---|---|---|
| Host repo allows no bot writes | Renovate/promote can't operate there | GitHub source-of-truth + one-way mirror (Phase 3 variant, already designed) |
| IT suite too slow even sharded | merge→staging latency grates | more shards (free on public repos); if still bad, flip to publish-after-units with ITs gating *promote* — workflow-order change only |
| GH Packages auth friction for contributors | annoying first-time setup | documented one-time PAT; curated releases on Maven Central for outsiders |
| Security audit blocks public country repos | openness goal delayed | repos run private meanwhile; nothing else changes |
| The country FE overlay does not translate cleanly to an npm dependency | Phase 8 stalls | **resolved by the country split** ([`docs/fe-country-split-plan.md`](../../../docs/fe-country-split-plan.md), P4–P7): no npm dependency; a country sets up from the source zip `niord-fe-src`, fills the seams in its own repository and builds its frontend and images there. The fallback of the time (`niord` building every variant and publishing their bundles and the public site's images) ended in P7 |
| The three repositories are private on GitHub Free until the split is complete (decided 2026-10-06) | 2,000 shared minutes, 500 MB of Packages: at 62 merges a month, country pipelines per publish add ~900 minutes; bundles per publish add ~5 MB to the ~9 MB a publish stores | country pipelines on a schedule or by dispatch while private; a prune of package versions; GitHub Team if the budget still binds; public together after the audit, when all of it is free |
| No ingress/Gateway controller on the cluster (found 2026-09-22) | the infra chart's Ingress objects would be silently ignored; the SECOM cutover reasoning assumes an ingress controller | **resolved on test 2026-09-26:** our own Traefik (`devops-shared`, `platform/test/traefik/`) and the chart's `proxy.ingress`; SECOM Edition 2 takes a peer's identity from the signed envelope, so SECOM rides through it as ordinary HTTPS; cert-manager to follow. Prod: ask the host about its HTTPS offloader (H6) |
| Live-prod cutover complexity (data migration, DNS) | out of this plan's scope | platform ready at Phase 4; cutover planned separately |
