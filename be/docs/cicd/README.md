# Niord CI/CD & deployment

Design and plan for how Niord (generic + DK + GL) is built, tested, and deployed — GitHub → staging through reviewed bump PRs (never automerged), production by button, GitOps on Kubernetes.

| Document | Read it for |
|---|---|
| [`intended-use.md`](intended-use.md) | **Start here.** Plain-language walkthrough of what it's like to use — for developers and stakeholders |
| [`design.md`](design.md) | The full technical design: repositories, versioning, propagation (the Niord base bump app for the countries; the deploy repository's leg as designed), Argo CD layout, promotion, secrets, snapshots |
| [`implementation-plan.md`](implementation-plan.md) | Phased build-out with acceptance criteria, sizes, and fallbacks |

**Status (2026-10-26; the bump: 2026-11-03):** design agreed 2026-07-07. The deploy and platform repos exist on the host's GitLab and the **test cluster is bootstrapped through Argo CD** (below). Every green merge to `main` publishes `4.0.<run>` (the generic image and the chart to Harbor, the library, the administration bundle (`en`) and the image tools to GitHub Packages). **DK and GL staging run on the test cluster** from `devops-niord/envs/staging/` (DK since 2026-09-26, GL since 2026-09-29 — this line said "parked" until 2026-10-06; only prod is parked, for a mail relay, a domain and sealed secrets). **The split is complete:** the country backends left on 2026-10-06 (step B: `SIFA-DK/niord-dk` and `SIFA-DK/niord-gl` from their histories, their images built in the country repositories from the published product, sharing its dependency layer), their frontends in the country split's P5 and P6 (2026-10-22/23, [`docs/fe-country-split-plan.md`](../../../docs/fe-country-split-plan.md)), and since its P7 (4.0.97, 2026-10-25) `niord-ng` is the country-unaware base product; both countries pin 4.0.97. `niord-ng`'s publish builds `niord-app-en` only. Image is disabled in both countries (`disabled_manually`) and their `harbor` environments have no main-only deployment rule yet: both at the deploy step, on the owner's go. The countries' bump is the Niord base bump app's pull request, opened or moved at every publish, being built (F8, decision 133, 2026-11-03; design §4), on the Base bump workflow the kit built on 2026-11-02 (never automerged; the owner, 2026-10-25, 2026-11-01 and 2026-11-03); no Renovate is installed. Step C, the environments, is next; prod is not started. The three code repositories stay **private** until the going-public step of the order of work (the third, after the environments) and go public together then (design §5, §11). **The order of work since 2026-10-06** (`implementation-plan.md`, *The order of work*): the split, then the environments, then going public, then the rest. Staging may be down while the split is made and runs around the clock from the environments step on; until the repositories are public staging's pins move by hand and a country image follows its bump PR's merge; the bump PRs (the app's, each reviewed and merged by a person) arrive at every publish and start the country's Base bump workflow and CI, and the full country CI at every move comes with the free minutes. The product's home will be `NiordOrg/niord`; SIFA's two installations are `SIFA-DK/niord-dk` and `SIFA-DK/niord-gl`. Open items live in `design.md` §11, `devops-niord/docs/phase-0-answers.md` (host questions, with what is known internally) and the two repos' `open-issues.md`.

## Where things stand

The design, element by element, against what exists today:

| Design element | Today |
|---|---|
| `niord` (generic, public) | This monorepo, **`niord-ng`**: `be/` (Maven reactor `niord/` = `org.niord.base:niord-base`, `niord-app/`; `niord-dk/` and `niord-gl/` until 2026-10-06) + `fe/` (an Angular 22 workspace with two applications — the administration app in `fe/ui-apps/admin/` and the public site in `fe/ui-apps/info/` — the base product, country-unaware: a country builds both from the published source zip `niord-fe-src`). The product repository since the split (step B, 2026-10-06); since 2026-09-22 every green merge to `main` publishes `4.0.<run>` (`publish.yml`, below). Since 2026-09-22 the reactor parent is `org.niord:niord-parent` at `${revision}` (default `4.0.0-SNAPSHOT`), the design §3 scheme — the first Phase 1 items done in place. |
| `niord-dk`, `niord-gl` (country, public¹) | The repositories `SIFA-DK/niord-dk` and `SIFA-DK/niord-gl`: their backends since 2026-10-06 (step B), their frontends since the country split's P5 and P6 (2026-10-22/23, [`docs/fe-country-split-plan.md`](../../../docs/fe-country-split-plan.md)); `niord-ng` holds no country tree since that plan's P7. GL was added 2026-09 (#24) — it exists *before* the split, which the original plan did not foresee (it scheduled GL as Phase 5). |
| CI (`design.md` §5) | `.github/workflows/be-ci.yml` (unit tests ~2 min, integration tests ~7 min), `fe-ci.yml` for the administration app, with three work jobs and the `Frontend gate`: checks + builds (format, docs, paths, `contents:check`, lint, guard tests, build followed by `urls:check`), the unit tests, and the Example country (the country kit's example country set up, built, tested and linted, with its image; the untouched `init`, the fixture upgrade, and the upgrade test from the latest release's source zip); and `info-ci.yml` for the public site, with one work job and the `Info gate`: checks + builds (format, docs, lint, guard tests, unit tests, paths, `contents:check`, build with `urls:check` and the separation and first-visit checks); since P7 it builds the base product alone and packages no image (until then it also built DK and GL, checked their markers and layout, packaged both container images and ran their proxy test). From 2026-09-25 they ran only on pull requests into `main` once ready for review, not on drafts or on sub-PRs into `feature/**`, because Actions minutes were billed in the SIFA-DK organisation; since the move to the public `NiordOrg/niord4` (2026-11-17) they run on every pull request, drafts and sub-PRs included, and on pushes to `main`. Each workflow has one detection job, as few work jobs as it needs and a gate. Publishing: `.github/workflows/publish.yml` (2026-09-22) runs after Backend CI, Frontend CI and Info CI are green on `main` (Info CI since the review of PR #184: the source zip carries the public site's sources since P4, so a merge confined to the public site publishes a version too; a CI workflow whose path filter did not start it counts as passed) — or as a clearly labelled break-glass `workflow_dispatch` from `main` after unit tests only, refused unless its triggering actor is on `.github/maintainers`. It builds the reactor once as `4.0.<run>` (`-Drevision`) without re-running the tests: its gate only publishes a commit whose backend passed Backend CI (unit + integration tests), for a frontend-only merge the run of the nearest backend-changing ancestor. It deploys `niord-parent` and `niord-base` (+ test-jar) to GitHub Packages (deployables are never jars) and, since 2026-10-06 (#128), the administration app's bundle as `org.niord.web:niord-web-admin` (the generic build under the classifier `en`; versions before P7 also carry `dk` and `gl`) and, from P4, the frontend source zip `org.niord.web:niord-fe-src`, which a country sets up from (the base product's frontend sources, built from `country-kit/zip-include.json` and checked by its country-word guard; [`docs/fe-country-split-plan.md`](../../../docs/fe-country-split-plan.md) §3.1) — **to the registry of `NiordOrg/niord` since 2026-10-06 (#133)**, the product's public home, with a machine user's publish-only token from the `publish` environment (`main` only): the Maven registry is repository-scoped, so this private repository's own packages were readable by no other repository's workflow; the versions up to 4.0.54 are in this repository's registry — then — from the one job under the `harbor` environment — pushes `niord/niord-app-en` built from that build's jars (until 2026-10-06 also `niord/niord-app-dk` and `niord/niord-app-gl`, which the country repositories build since; `niord/<module>-be` until 4.0.49), then the chart as `oci://reg.sitcloud.dk/cu3504-mssb-brs/charts/niord:4.0.<run>`, and tags `v4.0.<run>` once all of it exists, then creates the GitHub release on that tag with the source zip's sha256 in its notes and the zip as an asset (from P4). Proven 2026-09-22 with `v4.0.1` (images) and `v4.0.2` (jars + chart + images); simplified 2026-09-24 (until then it re-ran the integration tests and rebuilt the country modules a second time against GitHub Packages, ~14 min; that second build is what left `v4.0.7` tagged without country images when an upstream Maven repository was down). Still missing: a sharded IT suite, a `pr-<n>` image path, the FE image. |
| Helm chart | `be/k8s/helm/niord`, versioned with the release (`Chart.yaml` holds `4.0.0-SNAPSHOT`; CI stamps version and appVersion `4.0.<run>`) — one chart, six components (app, proxy, postgres, keycloak, mailhog, and `info`, the public site, off by default and turned on by an environment with its country's image; [`docs/public-site-deploy-plan.md`](../../../docs/public-site-deploy-plan.md)) each behind an `enabled` flag, rendered as one complete stack per country, each in its own namespace (design §6, decided 2026-09-24); the `postgres.host` / `keycloak.host` / `smtp.host` seams for an app-only plus a shared infra-only release remain available but unused (the default values still render the OrbStack bundle). Deliberately **not** split into app/infra charts. Images are `image.{registry,repository,tag}` with upstream paths, re-pointed at the Harbor mirrors by `global.imageRegistry`, and `global.imagePullSecrets` reaches every pod; the Reloader subchart is gone (what replaced it, and why that is gone too: design §6, *Repo layout*). The app image tag defaults to the chart's appVersion (2026-09-24), so an environment's chart pin is also its app image pin. Published as OCI by `publish.yml` as `charts/niord:4.0.<run>` since 2026-09-22 (the test realm is the default, for local use and the test environments; `keycloak.mode: production` runs Keycloak on Postgres with it, `niord-web` limited to the environment's origin, 2026-09-29 — the deploy repo's open issue 1 lists the remaining seams). |
| Container image | `be/k8s/docker/Dockerfile` (one runtime image for any deployable; since 2026-10 built from the unpacked jar so that the third-party jars are a layer that is the same bytes on every build and Harbor stores it once — `scripts/split-jar.sh` + `scripts/publish-images.sh`, `docs/image-split-plan.md`) + `scripts/build-image.sh`, parameterised on the module since 2026-09-22 (`--module niord-gl`); local images carry the Harbor names, `niord/niord-app-<country>:<appVersion>`. `publish.yml` pushes `niord/niord-app-en` (the generic `niord-app`) to Harbor at `4.0.<run>`; from 2026-10-03 (`docs/image-split-plan.md` step 2) until the country modules left on 2026-10-06 it also pushed `niord/niord-app-dk` and `niord/niord-app-gl`, which the country repositories build since, and `niord/<module>-be` from 2026-09-22 to 4.0.49. Each country packages the public site's image (`fe/ui-apps/info/Dockerfile`) from its own build with `npm run image:info` in its repository and pushes it to Harbor as `niord-<cc>-info`, under its app image's tag, which the chart's `info` component runs; `info-ci.yml` packaged DK's and GL's until P7. Since 2026-09-26 each backend image also carries its deployable's production build of the administration app (`publish.yml`'s `web` job; locally `build-image.sh`), which the backend serves at `/` (design §11, the frontend-image decision). |
| `niord-deploy` (private) | **`devops-niord`** on the host's GitLab, `git.sitcloud.dk/cu3504-mssb-brs/devops-niord` (moved from the GitHub sandbox `niord-devops` on 2026-09-17; local checkout `~/dma/sitcloud/Github/devops-niord`).
